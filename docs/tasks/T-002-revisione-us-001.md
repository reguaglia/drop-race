# T-002: Revisione della user story US-001 (Versione 2)

Stato: chiuso
Esecutore: code-reviewer
Milestone: 4
Dipendenze: T-001

## Obiettivo
Rivedere la Versione 2 delle user story contenuta nell'Esito di T-001 per
tracciabilità rispetto ai requisiti, verificabilità dei criteri, assenza di
regole inventate e Punti aperti lasciati non decisi.

## Riferimenti
- `docs/tasks/T-001-user-story-gocce.md`, sezione `## Esito` → `### Versione 2`.
- `docs/requirements.md`.
- `docs/tasks/roadmap.md`.
- `docs/tasks/TEMPLATE.md`.
- `AGENTS.md`.

## Criteri di accettazione
- [ ] La revisione produce al massimo 8 voci.
- [ ] Ogni voce riporta una gravità esplicita.
- [ ] Ogni voce cita il testo esatto a supporto (documento revisionato e, se
      pertinente, requisito).
- [ ] Ogni voce propone una correzione concreta.
- [ ] La revisione copre i quattro aspetti dell'Obiettivo: tracciabilità,
      verificabilità, assenza di regole inventate, Punti aperti non decisi.
- [ ] Nessun file viene modificato dal revisore.

## Fuori perimetro
- Modifica di T-001, `docs/requirements.md`, `docs/tasks/roadmap.md`,
  `AGENTS.md` o altri file.
- Riscrittura integrale della user story o produzione di una nuova versione.
- Scelta o risoluzione dei Punti aperti.
- Implementazione di UI, componenti React, Canvas o logica di simulazione.

## Da decidere
- Applicazione delle correzioni proposte dal revisore e relativa nuova versione
  della user story: spetta al committente.
- Promozione della user story revisionata in `docs/acceptance/`: spetta al
  committente.
- Eventuali Punti aperti che la revisione dovesse far emergere: restano decisioni
  del committente.
